=======================================================================
  COMO PUBLICAR UMA ATUALIZAÇÃO PARA TODOS OS PROFESSORES
=======================================================================

Este arquivo é para QUEM MANTÉM o programa (você), não para os
professores que só usam.


-----------------------------------------------------------------------
A ROTINA, EM DUAS LINHAS
-----------------------------------------------------------------------

    1. Suba os arquivos corrigidos aqui no GitHub.
    2. Aumente o número dentro do VERSAO.txt.

Só isso. O resto acontece sozinho.


-----------------------------------------------------------------------
O QUE ACONTECE SOZINHO
-----------------------------------------------------------------------

Assim que você sobe qualquer mudança, o GitHub:

  1. Empresta um computador com Windows;
  2. monta o Registro-SED.exe com o código novo;
  3. confere se o executável saiu inteiro (se não saiu, ele para e NÃO
     publica nada — ninguém recebe versão quebrada);
  4. publica em "Releases", com o número da versão;
  5. atualiza o arquivo versao.json, que é o que avisa os professores.

Leva uns 5 minutos. Você acompanha na aba "Actions" lá em cima:
bolinha amarela = montando, verde = publicado, vermelha = deu problema
(clique nela para ver em que passo parou).

Aí, quando cada professor abrir o programa, ele vê:

    "Saiu a versão X. Atualizar agora?"

Ele aceita, o programa se troca e reabre sozinho. Se ele disser não,
continua usando a versão antiga e o programa pergunta de novo na próxima
abertura — nunca troca nada sem o "sim" dele.


-----------------------------------------------------------------------
A REGRA DO NÚMERO DA VERSÃO
-----------------------------------------------------------------------

O VERSAO.txt é o que dispara tudo. Se você corrigir alguma coisa e
esquecer de aumentar o número, o .exe até é montado, mas NINGUÉM recebe:
o programa de cada professor compara justamente esse número.

    1.2.0  ->  1.2.1     correção pequena
    1.2.0  ->  1.3.0     recurso novo
    1.2.0  ->  2.0.0     mudança grande


-----------------------------------------------------------------------
O QUE A ATUALIZAÇÃO NUNCA TOCA
-----------------------------------------------------------------------

    .env                       (CPF e senha de cada professor)
    browser_profile/           (login do Google da escola)
    registros_enviados.json    (o que já foi enviado à SED)
    aulas_nao_realizadas.json
    ultimo_professor.txt

Quando o programa se troca, o executável antigo fica guardado ao lado
como "Registro-SED.antigo.exe" até a abertura seguinte. Se uma versão
sair com defeito, dá para apagar o novo e renomear esse de volta.

E o mais importante: publique logo uma versão corrigida, com o número
maior. Ela chega para todo mundo do mesmo jeito.


-----------------------------------------------------------------------
O QUE NUNCA SUBIR PARA CÁ
-----------------------------------------------------------------------

Este repositório é PÚBLICO. Nunca envie:

    .env                    (tem CPF e senha)
    browser_profile/        (tem o login do Google da escola)
    os arquivos .json de histórico

O arquivo .gitignore já bloqueia isso para quem usa o Git pelo programa,
MAS a tela de "Upload files" do site do GitHub não respeita o
.gitignore: ali, o que você arrastar, sobe. Confira o que está
selecionando.

Se um dia subir sem querer, não basta apagar o arquivo depois — o
histórico guarda. Nesse caso: troque a senha da agenda na hora e me
chame para limpar o histórico do repositório.


-----------------------------------------------------------------------
E SE O NTE/SED QUISER HOSPEDAR NO SERVIDOR DELES?
-----------------------------------------------------------------------

Funciona igual, sem reescrever nada: eles hospedam os mesmos arquivos
(versao.json + o .exe), e cada professor troca só a linha
URL_ATUALIZACAO do .env para o endereço novo.

Foi feito assim de propósito — o endereço é configuração, não está
gravado dentro do programa.
